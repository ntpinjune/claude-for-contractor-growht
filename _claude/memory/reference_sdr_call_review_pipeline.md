# SDR Call Review Pipeline

Built 2026-04-23 after Noah asked for Jowanna's calls to be reviewed. First working version end-to-end.

## Stack

- **Transcription:** `mlx-whisper` (Apple Silicon optimized, ~27x realtime on M-series)
- **Audio decoding:** `ffmpeg` from `imageio-ffmpeg` PyPI package (no Homebrew needed)
- **Scoring rubric:** `business/sops/sdr-call-rubric.md` — 50-point scale, 10 sections mirroring the Setter/Closing Script

## Tool paths (already installed on Noah's machine)

- `mlx_whisper` — installed via `uv tool install mlx-whisper`
- `ffmpeg` — symlinked to `~/.local/bin/ffmpeg` from `/Users/admin/Library/Python/3.9/lib/python/site-packages/imageio_ffmpeg/binaries/ffmpeg-macos-aarch64-v7.1`
- Both require `export PATH="$HOME/.local/bin:$PATH"` in the session

## Folder convention

UPDATED 2026-04-23: moved from `sdr-calls/` to employee-centric structure per Noah's preference. He manages people, not dates.

```
business/employees/{name}/call-recordings/YYYY-MM-DD/
├── audio/          # raw .wav files from GHL (keep originals)
├── transcripts/    # .txt files auto-generated by mlx_whisper
├── scorecards/     # per-call scorecards + SUMMARY-YYYY-MM-DD.md
└── JOWANNA-COACHING-DOC.{md,html,pdf}  # the packaged doc for the employee
```

Old `sdr-calls/` directory is deprecated; delete if it reappears.

## Standard workflow (per batch of SDR calls)

1. **Collect audio.** Noah or VA downloads the week's call recordings from GHL admin into `~/Downloads/`. Move them to `business/employees/{sdr-name}/call-recordings/YYYY-MM-DD/audio/`.

2. **Transcribe.** Run:
   ```bash
   export PATH="$HOME/.local/bin:$PATH"
   cd ~/Obsidian/ContractorGrowth/business/employees/{sdr-name}/call-recordings/YYYY-MM-DD
   for f in audio/*.wav; do
     mlx_whisper "$f" \
       --model mlx-community/whisper-base.en-mlx \
       --output-dir transcripts/ \
       --output-format txt
   done
   ```
   Base.en is fast + decent. Upgrade to `whisper-small.en-mlx` or `whisper-medium.en-mlx` if accuracy matters more than speed (first call of a new rep's review batch is good to upgrade).

3. **Run transcriptions in background** for batches over 20 min audio — use `run_in_background: true` and wait for the task-notification. 28-min call = ~60 seconds at 27x realtime.

4. **Score each transcript** against `business/sops/sdr-call-rubric.md`. Use the 10-section rubric. Write one scorecard per call into `scorecards/call-N-{filename}.md`.

5. **Write a daily summary scorecard** at `scorecards/SUMMARY-YYYY-MM-DD.md` that calls out:
   - Score table (all calls at a glance)
   - Patterns across the day (repeated failures across multiple calls)
   - Top 3 coaching priorities ranked by leverage
   - Accountability context (did the SDR log their numbers in the tracking sheet?)

## Known limitations

- **base.en hallucinates on silence.** Seen ~100-line "no, no, no" loops when the audio has long quiet stretches. Note it in the scorecard, don't score on hallucinated content. Upgrade model if it's a problem.
- **No speaker diarization.** Whisper doesn't separate speakers. For phone calls where only the SDR matters, this is OK. For multi-speaker analysis, would need AssemblyAI or pyannote.
- **One-way: transcript/scorecard → vault only.** If SDRs check off items or read scorecards, that feedback doesn't flow back to the pipeline.

## When to rebuild vs reuse

- **Reuse this:** every weekly SDR review batch.
- **Rebuild only if:** switching to AssemblyAI for speaker diarization, moving to automated GHL API pull, or scoring multiple SDRs simultaneously in parallel.
